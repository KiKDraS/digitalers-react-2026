Conceptos Fundamentales de React

Componentes, State y Props: La base para construir aplicaciones modernas

🧩 1. Componentes: Los Bloques de Construcción

Un Componente es el corazón de React. Es una pieza de código (generalmente una función) que devuelve una parte de la Interfaz de Usuario (UI) que se renderizará en la pantalla.

Analogía: Piensa en un componente como un módulo o una pieza de LEGO con un propósito específico (un botón, una tarjeta de producto, el encabezado de una página).

Reutilizabilidad: Defines el componente una vez, y lo usas donde quieras en tu aplicación. Al juntar muchos componentes, construyes la interfaz completa.

// Ejemplo de un componente funcional en React
function Boton() {
  return (
    <button>Haz clic aquí</button>
  );
}

// Uso del componente
function App() {
  return (
    <div>
      <h1>Mi Aplicación</h1>
      <Boton />
    </div>
  );
}

🎁 2. Props (Propiedades): Pasar Información

Las Props (abreviatura de Properties) son la forma en que los datos se pasan de un componente padre a un componente hijo. Son la principal vía de comunicación entre componentes.

Analogía: Son como los argumentos o parámetros que le pasas a una función.

Flujo Unidireccional: Las props viajan siempre hacia abajo en la jerarquía (del padre al hijo), como una cascada.

Inmutabilidad: Las props son solo de lectura. El componente hijo las recibe, pero no puede cambiarlas. Solo el componente padre tiene el control de la información que pasa.

// Componente Boton que recibe props
function Boton({ color, texto }) {
  return (
    <button style={{ backgroundColor: color }}>
      {texto}
    </button>
  );
}

// Uso del componente con diferentes props
function App() {
  return (
    <div>
      <Boton color="azul" texto="Comprar Ahora" />
      <Boton color="rojo" texto="Cancelar" />
    </div>
  );
}

🔄 3. State (Estado): La Memoria del Componente

El State (Estado) es la información o los datos internos y privados que un componente gestiona por sí mismo. A diferencia de las props (datos externos), el state está diseñado para cambiar con el tiempo y en respuesta a la interacción del usuario.

Reactividad: El state es la única razón por la que un componente se actualiza. Cuando el state cambia (ej. un usuario hace clic en un contador), React automáticamente "vuelve a renderizar" (dibuja de nuevo) el componente en la pantalla con los nuevos datos.

Concepto Clave: La UI es una función del state. UI = f(State).
// Componente con estado usando el hook useState
import { useState } from 'react';

function Contador() {
  // Declaración del estado
  const [contador, setContador] = useState(0);

  // Función para incrementar el contador
  const incrementar = () => {
    setContador(contador + 1);
  };

  // Función para decrementar el contador
  const decrementar = () => {
    setContador(contador - 1);
  };

  return (
    <div>
      <h2>Contador: {contador}</h2>
      <button onClick={incrementar}>+</button>
      <button onClick={decrementar}>-</button>
    </div>
  );
}

🧠 ¿Cómo se deben pensar las aplicaciones de React?

Pensar "en React" es un proceso de ingeniería inversa: vas de la interfaz visible al código, siguiendo estos pasos:

1

Dividir la Interfaz en Componentes

Mira el diseño de tu aplicación e identifica cada elemento que pueda ser una pieza independiente. Dibuja cajas alrededor de cada parte (encabezado, lista de productos, tarjeta individual, botón).

Ejemplo: Una red social se divide en: <App /> (el padre), <BarraLateral />, <Feed />, y dentro del Feed, múltiples <Publicacion />.

2

Identificar el State Mínimo Necesario

Pregúntate: "¿Qué información necesita cambiar en el tiempo para que la interfaz se vea diferente?"

  • Lista de productos (cambia al filtrar).
  • Texto de búsqueda (cambia al escribir).
  • El usuario actualmente autenticado (cambia al iniciar sesión).

Esta información es tu State.

3

Determinar Dónde Vive el State (Elevación del Estado)

El State debe residir en el componente más alto (más arriba en el árbol) que lo necesite.

Regla: Si dos componentes hermanos necesitan el mismo dato, el State debe vivir en su componente padre común.

Movimiento: Si el State comienza en un componente hijo, pero otro hermano también lo necesita, debes "elevar" el State al componente padre.

4

Flujo de Comunicación: Props

Una vez que el State está en el componente padre correcto, se utiliza para alimentar a los componentes hijos a través de Props.

  • El componente padre gestiona el State.
  • El componente hijo recibe el dato a través de Props.
  • Si el hijo necesita cambiar el State, le pide al padre que lo haga (pasándole una función como Prop), manteniendo el flujo de datos predecible.

Este proceso garantiza que tu aplicación sea modular, fácil de depurar y altamente reactiva.
