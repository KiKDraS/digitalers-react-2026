Clase Práctica: Todo App con React, TypeScript y Redux Toolkit 🚀

Vamos a construir una aplicación de lista de tareas conectada a una API real (MockAPI), usando React, TypeScript y Redux Toolkit.

Documentación TypeScript | Documentación Redux Toolkit | Documentación Vite | Documentación Bootstrap

Conceptos que Aplicaremos

  • React: Crearemos componentes reutilizables (Button, Section, Spinner) y componentes de feature (TodoList, TodoItem) que se "componen" para formar la aplicación.
  • TypeScript (TS): Usaremos TS para definir "contratos" (interfaces y types) para nuestros datos, props y estado.
  • Redux Toolkit (RTK): Manejaremos el estado de forma centralizada, incluyendo la lógica asíncrona (createAsyncThunk) para hablar con una API.
  • MockAPI: Nuestro servidor "falso" que nos permitirá hacer peticiones GET, POST, PUT y DELETE reales.
  • Bootstrap y Bootstrap Icons: Para que nuestra aplicación se vea limpia y profesional.

Parte 1: ¿Qué es TypeScript y en qué se diferencia de JavaScript?

TypeScript (TS) es un superconjunto de JavaScript. Esto significa que es "JavaScript con superpoderes". Todo el código JavaScript válido es también código TypeScript válido, pero TS añade un componente clave: Tipado Estático.

Analogía: Escribir JavaScript es como construir con Legos sin instrucciones. Escribir TypeScript es como construir con los mismos Legos, pero con un manual (los "tipos") que te avisa si intentas poner una pieza donde no va.

El navegador no entiende TypeScript. Por eso, tenemos un paso de "compilación" (que Vite hace por nosotros) que transforma nuestro código .ts o .tsx en código .js normal que el navegador sí puede ejecutar.

Diferencias Clave: Tipado Dinámico vs. Tipado Estático

JavaScript (Tipado Dinámico)

Los tipos de las variables se comprueban en tiempo de ejecución (cuando el código ya está en el navegador). Esto puede llevar a errores inesperados que el usuario final experimenta.


// Código JavaScript Válido
function sumar(a, b) {
  return a + b;
}

// Bug silencioso: '10' + '5' = "105" (concatenación)
const resultado = sumar(10, "5");
console.log(resultado); // Muestra "105"

TypeScript (Tipado Estático)

Los tipos se comprueban en tiempo de desarrollo (mientras escribes el código). Tu editor (como VS Code) te avisa de los errores antes de que llegues al navegador.


// Código TypeScript
function sumar(a: number, b: number): number {
  return a + b;
}

// ¡ERROR! TypeScript nos detiene aquí.
// El editor subraya "5" y dice:
// "Argument of type 'string' is not assignable to parameter of type 'number'."
const resultado = sumar(10, "5");

Herramientas Básicas de TypeScript que Usaremos

1. Tipos Primitivos


let nombre: string = "Ana";
let edad: number = 25;
let estaActivo: boolean = true;
let cualquierCosa: any = "Intentar evitar 'any'"; // 'any' desactiva TS

2. Tipado de Funciones


// Esta función debe recibir un 'string' y no debe devolver nada ('void')
const saludar = (nombre: string): void => {
  console.log("Hola, " + nombre);
}

3. Union Types (Unión de Tipos)

Un union type permite que una variable sea uno de varios tipos. TypeScript valida en tiempo de compilación que el valor sea válido.


// src/components/button/types.ts
// ButtonColor solo puede ser UNO de estos strings
export type ButtonColor =
  | "primary"
  | "secondary"
  | "warning"
  | "success"
  | "info"
  | "danger"
  | "dark"
  | "light";

// Uso: si pasamos color="azul", TS lo rechaza en compilación

4. Interfaces (El Molde o Contrato)


// src/features/todo/types/Todo.ts
// Tipo de dominio: representa un todo de la API
export interface Todo {
  id: string;
  text: string;
  completed: boolean;
}

const miTarea: Todo = {
  id: "1",
  text: "Aprender TS",
  completed: false
};

5. Tipos Derivados del Store


// src/store/index.ts
// Tipos DERIVADOS: se calculan automáticamente a partir del store real.
// - RootState: la forma del estado global (ReturnType de getState).
// - AppDispatch: el tipo del dispatch (typeof store.dispatch).
export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

6. Hooks Tipados (La Magia)


// src/store/hooks/useAppDispatch.ts
import { useDispatch } from 'react-redux';
import type { AppDispatch } from '../index';

// Hook tipado: evita escribir useDispatch<AppDispatch>() en cada componente
export const useAppDispatch: () => AppDispatch = useDispatch;
    

// src/store/hooks/useAppSelector.ts
import { useSelector, type TypedUseSelectorHook } from 'react-redux';
import type { RootState } from '../index';

// Hook tipado: el selector recibe el RootState automáticamente
export const useAppSelector: TypedUseSelectorHook<RootState> = useSelector;

Ahora, cuando usemos useAppSelector(state => ...), TypeScript sabrá que state tiene una propiedad todos.

¿Cuándo usar interface y cuándo usar type?

Es una de las dudas más comunes de TypeScript. La regla de oro:

Regla de oro: interface para objetos/contratos que se extienden. type para todo lo demás (unions, primitivos, tuplas, tipos derivados).

Usar interface cuando...

  • Es un objeto que describe una forma (datos de dominio, estado, props).
  • Necesitás extender con extends.
  • Necesitás declaration merging (dos interfaces con el mismo nombre se fusionan).

// Estructura de datos de dominio → interface
export interface Todo {
  id: string;
  text: string;
  completed: boolean;
}

// Props de componente → interface (estándar de React)
interface ButtonProps extends Omit<ButtonHTMLAttributes<HTMLButtonElement>, "color"> {
  text?: string;
  color?: ButtonColor;
}

Usar type cuando...

  • Es un union type (|).
  • Es un primitivo o tupla.
  • Es un tipo derivado (typeof, ReturnType).

// Union type → type
export type ButtonColor = "primary" | "secondary" | "danger";

// Tipo derivado del store → type
export type RootState = ReturnType<typeof store.getState>;

// Tipo derivado de un objeto as const → type
export type StatusType = (typeof STATUS)[keyof typeof STATUS];
Criterio interface type
Objetos / estructuras ✅ Preferida ✅ Funciona
Extender ✅ extends ✅ &
Declaration merging ✅ Sí ❌ No
Unions (|) ❌ No ✅ Sí
Primitivos / tuplas ❌ No ✅ Sí
Tipos derivados (typeof, ReturnType) ❌ No ✅ Sí
Resumen en una frase: Si es un objeto que describe una forma (y quizás se extienda) → interface. Si es una combinación de tipos (union, intersección, derivado) → type.

¿Qué es un tipo Genérico en TypeScript? 🧩

Un tipo genérico es un tipo que funciona como una "plantilla": recibe un parámetro de tipo (entre <>) que le indica con qué tipo concreto debe trabajar. Es como una función, pero de tipos: la función recibe valores y devuelve un resultado; el genérico recibe un tipo y devuelve un tipo especializado.

Analogía: Un molde de galletas es un "genérico". El molde es siempre el mismo, pero podés usarlo con masa de chocolate, vainilla o limón. El molde no sabe qué masa va a recibir — vos se lo indicás al usarlo. Igual que el genérico: la estructura es fija, pero el tipo concreto lo decidís vos.

¿Cómo funcionan?

Se declaran con una letra (convención: T de "Type") entre <>. Ese parámetro actúa como un "placeholder" que se reemplaza por el tipo real cuando se usa.

Ejemplo básico: una caja que guarda cualquier cosa


// T es el parámetro genérico: "el tipo de lo que guarda la caja"
interface Caja<T> {
  contenido: T;
}

// Al usarla, le decimos el tipo concreto
const cajaDeNumeros: Caja<number> = { contenido: 42 };
const cajaDeStrings: Caja<string> = { contenido: "hola" };

// Si intentamos meter un string en una Caja<number>, TS lo rechaza:
// const error: Caja<number> = { contenido: "hola" }; // ❌ ERROR

Ejemplo con funciones


// La función recibe un valor de tipo T y devuelve ese mismo tipo
function identidad<T>(valor: T): T {
  return valor;
}

const numero = identidad<number>(42); // numero: number
const texto = identidad("hola");       // TS infiere T = string

Genéricos en nuestro proyecto

Ya usamos genéricos en varios lugares sin darnos cuenta:

1. useState<string> — el estado tipado


// Le decimos a useState qué tipo de dato va a almacenar
const [text, setText] = useState<string>("");

2. SubmitEvent<HTMLFormElement> — el evento tipado


// SubmitEvent es un tipo GENÉRICO: necesita que le indiquemos con el type
// HTMLFormElement que este SubmitEvent corresponde a un evento de formulario
// HTML y no a otra cosa. Así e.target queda tipado como HTMLFormElement.
const handleSubmit = (e: SubmitEvent<HTMLFormElement>) => {
  e.preventDefault();
};

3. Omit<Todo, "id"> — modificar un tipo existente


// Omit recibe DOS parámetros: el tipo original y las keys a quitar.
// Resultado: el tipo Todo pero SIN la propiedad "id" (la genera el backend).
const newTodo: Omit<Todo, "id"> = { text, completed: false };

4. PropsWithChildren y TypedUseSelectorHook<RootState>


// PropsWithChildren: agrega la prop children a cualquier tipo de props
export const Section = ({ children }: PropsWithChildren) => { ... };

// TypedUseSelectorHook<RootState>: el hook de Redux "sabe" la forma del estado
export const useAppSelector: TypedUseSelectorHook<RootState> = useSelector;
¿Por qué importa? Los genéricos nos dan reutilización con seguridad: escribimos la lógica una sola vez (el molde) y TypeScript valida que cada uso tenga el tipo correcto. Sin genéricos, tendríamos que duplicar código o usar any (que desactiva la seguridad de tipos).

Parte 3: Lógica Asíncrona con createAsyncThunk

Separamos los thunks (acciones asíncronas) del slice (estado). Cada thunk genera tres acciones: pending, fulfilled y rejected.

src/features/todo/thunks.ts


import { createAsyncThunk } from '@reduxjs/toolkit';
import type { Todo } from './types/Todo';

const BASE_URL = 'https://tu-id.mockapi.io/todos';

// createAsyncThunk: crea acciones async (pending/fulfilled/rejected)

// GET
export const fetchTodos = createAsyncThunk('todos/fetchTodos', async () => {
  const response = await fetch(BASE_URL);
  if (!response.ok) throw new Error('Error getting todos');
  const data: Todo[] = await response.json();
  return data;
});

// POST
export const addTodo = createAsyncThunk('todos/addTodo', async (text: string) => {
  // Omit<Todo, "id">: el tipo Todo sin la key "id" (la genera el backend)
  const newTodo: Omit<Todo, 'id'> = { text, completed: false };

  const response = await fetch(BASE_URL, {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify(newTodo),
  });
  if (!response.ok) throw new Error('Error creating todo');
  const data: Todo = await response.json();
  return data;
});

// PUT
export const toggleTodo = createAsyncThunk('todos/toggleTodo', async (todo: Todo) => {
  const response = await fetch(`${BASE_URL}/${todo.id}`, {
    method: 'PUT',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify({ completed: !todo.completed }),
  });
  if (!response.ok) throw new Error('Error updating todo');
  const data: Todo = await response.json();
  return data;
});

// DELETE
export const deleteTodo = createAsyncThunk('todos/deleteTodo', async (id: string) => {
  const response = await fetch(`${BASE_URL}/${id}`, { method: 'DELETE' });
  if (!response.ok) throw new Error('Error deleting todo');
  const data: Todo = await response.json();
  return data.id;
});

src/features/todo/constants/STATUS.ts


export const STATUS = {
  IDLE: 'idle',
  PENDING: 'pending',
  FULFILLED: 'fulfilled',
  REJECTED: 'rejected',
} as const;
// as const -> Cada key del objeto STATUS tiene un dato idéntico al valor que almacena

// StatusType tiene que ser una de las key del objeto as const STATUS

src/features/todo/slice.ts


import { createSlice, isRejected, type PayloadAction } from '@reduxjs/toolkit';
import { STATUS } from './constants/STATUS';
import type { Todo } from './types/Todo';
import type { TodosState } from './types/TodosState';
import { addTodo, deleteTodo, fetchTodos, toggleTodo } from './thunks';

const initialState: TodosState = {
  todos: [],
  status: STATUS.IDLE,
  error: null,
};

export const todoSlice = createSlice({
  name: 'todos',
  initialState,
  reducers: {
    // Reducers sincrónicos
  },
  extraReducers: (builder) => {
    builder
      // GET Cases
      .addCase(fetchTodos.pending, (state) => {
        state.error = null;
        state.status = STATUS.PENDING;
      })
      .addCase(fetchTodos.fulfilled, (state, action: PayloadAction<Todo[]>) => {
        state.status = STATUS.FULFILLED;
        state.todos = action.payload;
      })
      // Error case EXPLÍCITO: tiene prioridad sobre el matcher global.
      // Solo se ejecuta si el error viene de fetchTodos.
      .addCase(fetchTodos.rejected, (state, action) => {
        state.status = STATUS.REJECTED;
        state.error = action.error.message || 'Error al cargar las tareas';
      })
      // POST Cases
      .addCase(addTodo.fulfilled, (state, action: PayloadAction<Todo>) => {
        state.todos.push(action.payload);
      })
      // PUT Cases
      .addCase(toggleTodo.fulfilled, (state, action: PayloadAction<Todo>) => {
        const index = state.todos.findIndex(
          (todo) => todo.id === action.payload.id
        );
        if (index !== -1) {
          state.todos[index] = action.payload;
        }
      })
      // DELETE Cases
      .addCase(deleteTodo.fulfilled, (state, action: PayloadAction<string>) => {
        state.todos = state.todos.filter((todo) => todo.id !== action.payload);
      })
      // Global Error Handler (solo se ejecuta si no se explicita el error case)
      .addMatcher(isRejected, (state, action) => {
        state.status = STATUS.REJECTED;
        state.error = action.error.message || 'Something went wrong with the todos slice';
      });
  },
});

export const todosReducer = todoSlice.reducer;
Nota sobre isRejected: El matcher isRejected captura el error de cualquier thunk de forma global, sin necesidad de escribir un .addCase(...rejected) para cada uno. Pero si definís un error case explícito (como fetchTodos.rejected), ese tiene prioridad y el matcher global no se ejecuta para ese thunk. Es útil cuando querés un mensaje de error específico para una operación puntual.

import type { ButtonHTMLAttributes, ReactNode } from 'react';
import { colorMapper } from './constants/colorMapper';
import type { ButtonColor } from './types';

// Omit: quita "color" de los atributos nativos del <button>
// para reemplazarlo por nuestro propio ButtonColor
interface ButtonProps extends Omit<ButtonHTMLAttributes<HTMLButtonElement>, 'color'> {
  // text es opcional: si no se pasa, se renderizan los children
  text?: string;
  color?: ButtonColor;
  children?: ReactNode;
}

export const Button = ({
  text,
  type = 'button',
  color = 'primary',
  className,
  children,
  ...rest
}: ButtonProps) => {
  return (
    <button
      type={type}
      className={`btn ${colorMapper[color]} ${className ?? ''}`}
      {...rest}
    >
      {/* children ?? text: usa children si existe, si no usa text */}
      {children ?? text}
    </button>
  );
};

src/features/todo/components/TodoForm.tsx


import { useState, type FormEvent } from 'react';
import { Button } from '../../../components/button/Button';
import { addTodo } from '../thunks';
import { useAppDispatch } from '../../../store/hooks/useAppDispatch';

export const TodoForm = () => {
  const [text, setText] = useState<string>('');
  const dispatch = useAppDispatch();

  const handleSubmit = (e: FormEvent) => {
    e.preventDefault();
    // Validar que el input no esté vacío
    if (text.trim() === '') return;

    dispatch(addTodo(text));
    setText('');
  };

  return (
    <form onSubmit={handleSubmit}>
      <div className="input-group">
        <input
          type="text"
          className="form-control"
          value={text}
          placeholder="¿Qué necesitas hacer?"
          onChange={(e) => setText(e.target.value)}
        />
        <Button type="submit" className="btn btn-primary">
          <i className="bi bi-plus-lg me-2"></i>
          Añadir
        </Button>
      </div>
    </form>
  );
};

src/features/todo/components/List/TodoList.tsx


import { useEffect } from 'react';
import { useAppDispatch } from '../../../../store/hooks/useAppDispatch';
import { fetchTodos } from '../../thunks';
import { useAppSelector } from '../../../../store/hooks/useAppSelector';
import { STATUS } from '../../constants/STATUS';
import { Spinner } from '../../../../components/Spinner';
import { TodoItem } from './TodoItem';

export const TodoList = () => {
  const dispatch = useAppDispatch();
  const todosState = useAppSelector((store) => store.todos);
  const { todos, status, error } = todosState;

  useEffect(() => {
    dispatch(fetchTodos());
  }, [dispatch]);

  if (status === STATUS.PENDING) {
    return <Spinner />;
  }

  // Si hubo un error, lo mostramos en vez de la lista
  if (status === STATUS.REJECTED) {
    return <div className="alert alert-danger">Error: {error}</div>;
  }

  return (
    <ul className="list-group">
      {todos.length === 0 ? (
        <li className="list-group-item text-center text-muted">
          ¡No hay tareas pendientes!
        </li>
      ) : (
        todos.map((todo) => <TodoItem key={todo.id} todo={todo} />)
      )}
    </ul>
  );
};

src/features/todo/components/List/TodoItem.tsx


import { Button } from '../../../../components/button/Button';
import { useAppDispatch } from '../../../../store/hooks/useAppDispatch';
import { deleteTodo, toggleTodo } from '../../thunks';
import type { Todo } from '../../types/Todo';

interface Props {
  todo: Todo;
}

export const TodoItem = ({ todo }: Props) => {
  const dispatch = useAppDispatch();

  const handleToggle = () => {
    dispatch(toggleTodo(todo));
  };

  const handleDelete = () => {
    dispatch(deleteTodo(todo.id));
  };

  const itemClasses = `list-group-item d-flex justify-content-between align-items-center ${
    todo.completed ? 'list-group-item-light text-muted' : ''
  }`;

  const iconClasses = `bi ${
    todo.completed ? 'bi-check-circle-fill text-success' : 'bi-circle'
  }`;

  const textClasses = `flex-grow-1 ${
    todo.completed ? 'text-decoration-line-through' : ''
  }`;

  return (
    <li className={itemClasses}>
      <div>
        {/* Icono para marcar como completado */}
        <Button
          className="btn btn-link p-0 me-3 text-decoration-none"
          onClick={handleToggle}
        >
          <i className={iconClasses}></i>
        </Button>

        {/* Texto de la tarea */}
        <Button
          className={`${textClasses} btn btn-link p-0 text-start`}
          onClick={handleToggle}
        >
          {todo.text}
        </Button>
      </div>

      {/* Botón de eliminar */}
      <Button className="btn btn-outline-danger btn-sm" onClick={handleDelete}>
        <i className="bi bi-trash3-fill"></i>
      </Button>
    </li>
  );
};
Nota sobre el Button reutilizable: El componente acepta tanto la prop text como children. Usa children ?? text: si hay children, los renderiza; si no, renderiza el texto. Esto lo hace flexible para ambos casos de uso.

Parte 5: Desplegando a GitHub Pages con Vite 🌍

Una vez que nuestra app funciona localmente, ¡vamos a publicarla en la web gratis!

Pre-requisito: Tu proyecto debe estar en un repositorio de GitHub y ya debes haber subido tu código (git push).

Paso 1: Configurar package.json


// package.json (ejemplo parcial)
{
  "name": "mi-todo-app",
  "homepage": "https://tu-usuario-github.github.io/tu-repositorio/",
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "preview": "vite preview",
    "predeploy": "npm run build",
    "deploy": "gh-pages -d dist"
  },
  // ... resto del package.json
}

Importante: Reemplaza tu-usuario-github y tu-repositorio con tus datos reales.

Paso 2: Configurar vite.config.ts (¡Crucial!)


// vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  base: '/tu-repositorio/',
})
Advertencia sobre React Router: Si en el futuro añades React Router y usas BrowserRouter, recuerda que con GitHub Pages la URL base no es la raíz. Deberás configurar el basename en el router o usar HashRouter para evitar errores 404 al recargar.

Paso 3: Ejecutar el Despliegue


npm run deploy

Paso 4: Activar GitHub Pages
