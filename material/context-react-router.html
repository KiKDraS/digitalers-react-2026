React: Context API y React Router 🚀

Manejando el estado global y la navegación en tu aplicación.

Parte 1: Context API (El "Walkie-Talkie" de React) 📢

Resuelve el problema del "Prop Drilling" (perforación de props), permitiendo que un componente "Abuelo" pase datos a un "Nieto" directamente, sin que el "Padre" tenga que actuar como intermediario.

Ejemplo básico: Un Switch de Tema (Dark/Light Mode)

Paso 1: Crear el Contexto (`ThemeContext.js`)


import { createContext } from 'react';
export const ThemeContext = createContext('light');

Paso 2: Proveer el Contexto (`App.js`)


import React, { useState } from 'react';
import { ThemeContext } from './ThemeContext';
import Navbar from './Navbar';

function App() {
  const [theme, setTheme] = useState('light');
  const toggleTheme = () => {
    setTheme(theme === 'light' ? 'dark' : 'light');
  };

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      <div className={theme === 'light' ? 'bg-light' : 'bg-dark'}>
        <Navbar />
        {/* ...más contenido... */}
      </div>
    </ThemeContext.Provider>
  );
}

Paso 3: Consumir el Contexto (`Navbar.js`)


import React, { useContext } from 'react';
import { ThemeContext } from './ThemeContext';

function Navbar() {
  const { theme, toggleTheme } = useContext(ThemeContext);
  return (
    <nav className={theme === 'light' ? 'navbar navbar-light bg-light' : 'navbar navbar-dark bg-dark'}>
      <button onClick={toggleTheme}>Cambiar tema</button>
    </nav>
  );
}

🎯 Mejores usos para Context API

Context API es ideal para estado global de solo lectura o que cambia con poca frecuencia y que muchos componentes necesitan consumir sin pasarlo manualmente por props.

🌙

Tema de la aplicación

Dark/Light mode que se aplica en toda la interfaz.


const { theme, toggleTheme } = useContext(ThemeContext);
👤

Autenticación y sesión

Usuario actual, rol y funciones de login/logout.


const { user, login, logout } = useContext(AuthContext);
🌍

Idioma / Localización (i18n)

Traducciones y cambio de idioma en cualquier componente.


const { t, locale, setLocale } = useContext(LocaleContext);
🛒

Carrito de compras

Estado compartido entre páginas de productos, carrito y checkout.


const { items, addItem, removeItem } = useContext(CartContext);
⚙️

Preferencias globales

Tamaño de fuente, densidad de interfaz, filtros activos.


const { fontSize, setFontSize } = useContext(SettingsContext);

⚠️ Cuándo NO usar Context (y cómo mitigar problemas)

Context es excelente para datos que cambian poco, pero cuando el estado cambia con mucha frecuencia (por ejemplo, cada pulsación de tecla), puede provocar re-renders en cascada en todos los componentes que consumen ese contexto, incluso si no usan la parte que cambió.

Ejemplo problemático:
Un solo contexto que mezcla tema (cambia poco) y valor de un input (cambia en cada tecla) fuerza a todos los consumidores a re-renderizarse al escribir. 

import React, { createContext, useContext, useState } from 'react';

const AppContext = createContext();

function AppProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const [inputValue, setInputValue] = useState(''); // cambia en cada tecla

  // Al cambiar inputValue, TODOS los consumidores se re-renderizan
  const value = { theme, setTheme, inputValue, setInputValue };

  return <AppContext.Provider value={value}>{children}</AppContext.Provider>;
}

function ThemeButton() {
  const { theme, setTheme } = useContext(AppContext);
  console.log('ThemeButton render');
  return <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>Cambiar tema</button>;
}

function TextInput() {
  const { inputValue, setInputValue } = useContext(AppContext);
  return <input value={inputValue} onChange={(e) => setInputValue(e.target.value)} />;
}

🛠️ Estrategias para mitigar re-renders innecesarios

  1. Dividir en contextos más pequeños: Separar dominios (tema, autenticación, formulario) para que un cambio solo afecte a los consumidores de ese contexto.
  2. Estabilizar el valor con useMemo y useCallback: Si el objeto value no cambia, los consumidores no se re-renderizan aunque el proveedor sí lo haga.
  3. Separar estado de UI y estado del dominio: El estado de un input (cambia rápido) no debería estar en el mismo contexto que los datos (cambian menos).
  4. Usar bibliotecas con suscripciones selectivas: Zustand o Redux Toolkit permiten que un componente se suscriba solo a una porción del estado.

📊 Regla práctica revisada

Criterio Context Alternativa
Frecuencia de cambios Baja o media (tema, usuario, configuración) Alta (inputs, animaciones) → estado local o biblioteca con selectores
Número de consumidores Muchos componentes leen el mismo dato Pocos consumidores → props o composición
Complejidad del estado Simple o media Compleja (muchas acciones) → useReducer + Context o Zustand/Redux

🔧 Ejemplo recomendado: Context + useReducer para un carrito de compras

Este patrón es útil cuando tienes un estado con múltiples acciones que modifican el mismo conjunto de datos. useReducer centraliza la lógica de actualización y Context lo distribuye. 


import React, { createContext, useContext, useReducer, useMemo } from 'react';

const CartContext = createContext();

const cartReducer = (state, action) => {
  switch (action.type) {
    case 'ADD_ITEM':
      return { ...state, items: [...state.items, action.payload] };
    case 'REMOVE_ITEM':
      return { ...state, items: state.items.filter(item => item.id !== action.payload) };
    case 'CLEAR_CART':
      return { ...state, items: [] };
    default:
      return state;
  }
};

function CartProvider({ children }) {
  const [state, dispatch] = useReducer(cartReducer, { items: [] });

  // Estabilizamos el value para evitar renders innecesarios
  const value = useMemo(() => ({ state, dispatch }), [state]);

  return <CartContext.Provider value={value}>{children}</CartContext.Provider>;
}

// Hook personalizado para consumir el carrito
function useCart() {
  const context = useContext(CartContext);
  if (!context) throw new Error('useCart debe usarse dentro de CartProvider');
  return context;
}

// Uso en un componente
function ProductList({ products }) {
  const { dispatch } = useCart();
  return (
    <div>
      {products.map(product => (
        <button key={product.id} onClick={() => dispatch({ type: 'ADD_ITEM', payload: product })}>
          Agregar {product.name}
        </button>
      ))}
    </div>
  );
}

function CartSummary() {
  const { state } = useCart();
  return <p>Total de items: {state.items.length}</p>;
}
💡 ¿Cuándo usar Context + useReducer?
Cuando tienes un estado moderadamente complejo (carrito, formulario multi-paso, lista de tareas) con varias acciones que lo modifican. Si la complejidad crece demasiado, considera Zustand o Redux Toolkit.

🔁 Alternativas modernas a Context

  • Zustand → estado global con suscripciones selectivas y menos boilerplate.
  • Redux Toolkit → aplicaciones grandes con lógica compleja, debugging poderoso.
  • Composición de componentes → evita prop drilling pasando JSX como children o render props, sin necesidad de estado global.

Parte 1.5: Optimizando Context con useMemo y useCallback

El Problema de Rendimiento:
Cada vez que el componente App se re-renderiza, crea un objeto value nuevo. React ve este objeto "nuevo" y fuerza a todos los componentes que consumen el contexto (Navbar) a re-renderizarse, incluso si theme no cambió.

Para solucionar esto, "estabilizamos" el valor con useMemo y useCallback.

  • useCallback(fn, [deps]): Memoriza una función. Solo la crea de nuevo si sus dependencias cambian.
  • useMemo(() => valor, [deps]): Memoriza un valor (objeto, array, cálculo). Solo lo recalcula si sus dependencias cambian.

Ejemplo: Estabilizando nuestro ThemeContext


import React, { useState, useMemo, useCallback } from 'react';
import { ThemeContext } from './ThemeContext';

function App() {
  const [theme, setTheme] = useState('light');

  // 1. Estabilizamos la función con useCallback
  const toggleTheme = useCallback(() => {
    setTheme(t => (t === 'light' ? 'dark' : 'light'));
  }, []); // Sin dependencias, la función nunca cambia

  // 2. Estabilizamos el objeto value con useMemo
  const value = useMemo(() => ({
    theme,
    toggleTheme
  }), [theme, toggleTheme]); // Solo se recalcula si theme o toggleTheme cambian

  return (
    <ThemeContext.Provider value={value}>
      <div className={theme === 'light' ? 'bg-light' : 'bg-dark'}>
        <Navbar />
        {/* ...más contenido... */}
      </div>
    </ThemeContext.Provider>
  );
}

¿Cuándo tiene sentido usar useMemo?

useMemo es útil cuando tienes un cálculo costoso que no quieres repetir en cada render. Por ejemplo, filtrar una lista grande o procesar datos complejos.

Ejemplo: Filtrar una lista grande


import React, { useState, useMemo } from 'react';

function ProductList({ products, category }) {
  // Sin useMemo: este filter se ejecutaría en cada render,
  // incluso si products y category no cambiaron.
  const filteredProducts = useMemo(() => {
    console.log('Filtrando productos...');
    return products.filter(p => p.category === category);
  }, [products, category]); // Solo recalcula si products o category cambian

  return (
    <ul>
      {filteredProducts.map(p => (
        <li key={p.id}>{p.name}</li>
      ))}
    </ul>
  );
}

Ejemplo: Cálculo derivado de un estado


const totalPrice = useMemo(() => {
  return items.reduce((sum, item) => sum + item.price * item.quantity, 0);
}, [items]);
💡 Regla práctica: Usa useMemo solo si el cálculo es realmente costoso o si necesitas referencias estables (como en el caso del Context). Para cálculos simples, es innecesario.

¿Cuándo tiene sentido usar useCallback?

useCallback es útil cuando pasas funciones a componentes hijos memorizados con React.memo. Si no usas React.memo, el hijo se re-renderizará de todos modos y useCallback no aporta beneficio.

Ejemplo: Pasar callback a un hijo memoizado


import React, { useState, useCallback, memo } from 'react';

const Button = memo(({ onClick, label }) => {
  console.log('Renderizando botón:', label);
  return <button onClick={onClick}>{label}</button>;
});

function Parent() {
  const [count, setCount] = useState(0);

  // Sin useCallback, esta función se crearía nueva en cada render,
  // lo que rompería la memoización del componente Button.
  const handleIncrement = useCallback(() => {
    setCount(c => c + 1);
  }, []); // Nunca cambia

  return (
    <div>
      <p>Contador: {count}</p>
      <Button onClick={handleIncrement} label="Incrementar" />
    </div>
  );
}

Ejemplo: Pasar callback a un contexto

Como vimos en el ThemeContext, usar useCallback para funciones que van dentro de un value de Context ayuda a evitar re-renders innecesarios en los consumidores.

⚠️ Ojo con la sobre-optimización:
No uses useCallback o useMemo por defecto en todas las funciones y valores. Añaden complejidad y pueden empeorar el rendimiento si se usan sin necesidad.
  • Si el componente hijo no está memoizado, useCallback no evita su re-render.
  • Si el cálculo es barato, useMemo solo añade overhead.

Resumen rápido

  • useMemo: para cálculos costosos o referencias estables (objetos en Context).
  • useCallback: para funciones pasadas a hijos memoizados o incluidas en Context.
  • No usar: si no hay un problema real de rendimiento o si el componente no está memoizado.

Parte 2: React Router DOM (El "Navegador GPS" de React) 🗺️

React Router es una librería que simula la navegación en una "Single Page Application" (SPA). Observa la URL y renderiza diferentes componentes sin recargar la página.

Componentes Clave

  • <BrowserRouter>: Envuelve toda tu aplicación, generalmente en App.js.
  • <Routes>: Define el área donde cambiarán las páginas.
  • <Route path="..." element="..." />: La regla de navegación.
  • <Link to="...">: Reemplaza a <a href> para navegar sin recargar.

Hooks Clave

  • useParams(): Lee parámetros dinámicos de la URL (ej. /user/:id).
  • useNavigate(): Permite redirigir al usuario (ej. después de un login).

Ejemplo: Definir Rutas básicas con createBrowserRouter (estándar actual)


// main.jsx — Configuración del router (data router)
import { createBrowserRouter, RouterProvider } from 'react-router-dom';
import { Layout } from './Layout';
import { HomePage } from './pages/HomePage';
import { AboutPage } from './pages/AboutPage';

// createBrowserRouter: define las rutas como OBJETOS (no como JSX).
// Es la API recomendada desde React Router v6.4.
const router = createBrowserRouter([
  {
    path: '/', // Ruta padre: su layout envuelve a todas las rutas hijas
    element: <Layout />, // Layout route: se renderiza SIEMPRE que matchee una ruta hija
    children: [
      // index: true → ruta por defecto del layout (se muestra en "/")
      { index: true, element: <HomePage /> },
      // Path relativo: "about" se resuelve como "/about"
      { path: 'about', element: <AboutPage /> },
    ],
  },
]);

function App() {
  // RouterProvider: monta el router y le da contexto de navegación a toda la app
  return <RouterProvider router={router} />;
}


// Layout.jsx — Componente de layout compartido
import { Outlet } from 'react-router-dom';
import { Navbar } from './Navbar';

export function Layout() {
  return (
    <div>
      <Navbar /> {/* Se muestra en TODAS las páginas hijas */}
      <div className="container mt-4">
        {/* Outlet: el "hueco" donde se renderiza la ruta hija que matchee */}
        <Outlet />
      </div>
    </div>
  );
}

Ejemplo: Usar useParams y useNavigate


// pages/UserProfile.js
import { useParams, useNavigate } from 'react-router-dom';

function UserProfile() {
  const { id } = useParams(); // obtiene el parámetro :id de la URL
  const navigate = useNavigate();

  const handleGoBack = () => {
    navigate(-1); // vuelve atrás en el historial
  };

  return (
    <div>
      <h2>Perfil del usuario {id}</h2>
      <button onClick={handleGoBack}>Volver</button>
    </div>
  );
}

// <Route path="/user/:id" element={<UserProfile />} />

Parte 3: Rutas Protegidas combinando Context y Router 🛡️

¿Cómo hacemos para que la ruta /admin solo sea accesible si el usuario tiene el rol de "admin"? Usaremos Context API para saber quién es el usuario, y React Router para decidir dónde puede ir.

Paso 1: Crear un AuthContext simple

Primero, un contexto para manejar la autenticación, con user, login y logout. 


// contexts/AuthContext.js
import React, { createContext, useState, useContext } from 'react';

const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null); // null = no logueado

  const login = (username, role) => setUser({ username, role });
  const logout = () => setUser(null);

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

export const useAuth = () => {
  const context = useContext(AuthContext);
  if (!context) throw new Error('useAuth debe usarse dentro de un AuthProvider');
  return context;
};

Paso 2: Crear el componente <RutaProtegida>

Este componente actúa como layout route: protege a sus rutas hijas. Si no hay usuario, redirige al login.


// components/RutaProtegida.js
import { Navigate, Outlet, useLocation } from 'react-router-dom';
import { useAuth } from '../contexts/AuthContext';

export function RutaProtegida() {
  const { user } = useAuth();
  const location = useLocation();

  if (!user) {
    // Redirigir al login guardando la ubicación intentada
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  // Si hay sesión, renderiza la ruta hija
  return <Outlet />;
}

Paso 3: Usar <RutaProtegida> como layout route


// main.jsx — Configuración del router (data router)
import { createBrowserRouter, RouterProvider } from 'react-router-dom';
import { Layout } from './Layout';
import HomePage from './pages/HomePage';
import LoginPage from './pages/LoginPage';
import RegistroPage from './pages/RegistroPage';
import PerfilPage from './pages/PerfilPage';
import AdminPage from './pages/AdminPage';
import { RutaProtegida } from './components/RutaProtegida';

const router = createBrowserRouter([
  {
    path: '/',
    element: <Layout />, // Layout route: envuelve a todas las rutas hijas
    children: [
      // ===== RUTAS PÚBLICAS =====
      // Accesibles para cualquiera: se agregan como hijas directas del Layout.
      // Cada ruta nueva solo necesita una línea aquí.
      { index: true, element: <HomePage /> },
      { path: 'login', element: <LoginPage /> },
      { path: 'registro', element: <RegistroPage /> },

      // ===== RUTAS PROTEGIDAS =====
      // Requieren sesión: se agrupan bajo RutaProtegida (layout route).
      // Agregar una ruta nueva dentro de este children la protege automáticamente.
      {
        element: <RutaProtegida />,
        children: [
          { path: 'perfil', element: <PerfilPage /> },
          { path: 'admin', element: <AdminPage /> },
        ],
      },
    ],
  },
]);

function App() {
  return <RouterProvider router={router} />;
}

¿Y si tengo más de una ruta pública o protegida? El patrón escala igual: las rutas públicas se agregan como hijas directas del Layout, y las protegidas se agrupan dentro de RutaProtegida. La lógica de protección se escribe una sola vez y aplica a todas las rutas hijas — no hace falta repetirla por cada ruta.

Paso 4 (Extra): Añadiendo roles

Podemos extender RutaProtegida para aceptar un roleRequerido.


export function RutaProtegida({ roleRequerido }) {
  const { user } = useAuth();
  const location = useLocation();

  if (!user) {
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  if (roleRequerido && user.role !== roleRequerido) {
    return <Navigate to="/no-autorizado" replace />;
  }

  return <Outlet />;
}

Parte 4: Seguridad en el Almacenamiento de Datos del Cliente 🔐

Al guardar datos en el navegador, debemos considerar la seguridad, especialmente con tokens de sesión.

Opciones de almacenamiento

Método Persistencia Vulnerable a XSS Uso recomendado
localStorage Sí (incluso al cerrar navegador) Sí Datos no sensibles (preferencias, caché)
sessionStorage Solo durante la pestaña Sí Datos temporales no sensibles
Cookies HttpOnly Depende de configuración No (si HttpOnly) Tokens de sesión (recomendado)
Estado de React (memoria) No (se pierde al refrescar) No directamente Datos sensibles durante la sesión activa
⚠️ Importante: Nunca guardes tokens de sesión o datos sensibles en localStorage o sessionStorage.

La forma más segura es usar cookies HttpOnly configuradas desde el servidor, que no son accesibles por JavaScript.
