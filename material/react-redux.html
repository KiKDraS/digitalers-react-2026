¿Por Qué Necesitamos Redux? (El Problema del Estado Complejo)

En aplicaciones React pequeñas, manejar el estado con useState y pasarlo con props funciona bien. Pero a medida que la aplicación crece, surgen problemas:

  • Prop Drilling: Tener que pasar props a través de muchos niveles de componentes, incluso si los intermedios no las usan.
  • Estado Disperso: La lógica y los datos relacionados pueden terminar esparcidos por muchos componentes, dificultando el seguimiento y la depuración.
  • Complejidad: Actualizar el estado de forma consistente se vuelve complicado cuando múltiples componentes interactúan con los mismos datos.

Redux ofrece una solución centralizando el estado de tu aplicación en un solo lugar y estableciendo reglas claras sobre cómo puede cambiar.

Analogía del Banco Central 🏦:
Imagina que el estado de tu app es el dinero de un país. En lugar de que cada persona (componente) imprima su propio dinero (maneje su estado localmente de forma caótica), Redux actúa como un **Banco Central** (el **Store**).
  • Todo el dinero (el **Estado**) está guardado en la bóveda del banco.
  • Si quieres hacer un depósito o retiro (cambiar el estado), no tocas el dinero directamente. Llenas un formulario (envías una **Acción**).
  • Un empleado del banco (el **Reducer**) toma tu formulario, verifica las reglas, y actualiza el saldo en la bóveda.
Es un sistema predecible y centralizado.

¿Cuándo usar Redux? 🤔

Redux no es necesario en todos los proyectos. Antes de decidir, considera:

  • Tamaño de la aplicación: En aplicaciones pequeñas o medianas, Context API o Zustand pueden ser suficientes.
  • Frecuencia de actualizaciones: Si el estado cambia muy seguido y es compartido por muchos componentes, Redux brinda herramientas de depuración y rendimiento.
  • Complejidad del estado: Muchas acciones, relaciones entre datos, necesidad de undo/redo, etc.
  • Equipo y escalabilidad: Redux impone una estructura que ayuda a que equipos grandes trabajen de forma consistente.
⚠️ Advertencia: No uses Redux por defecto. Para estados locales o datos que solo se comparten en una parte de la app, useState o Context API son más simples. Redux añade complejidad, así que debe justificarse.

Parte 1: Redux - La Librería de JavaScript Pura ⚙️

Es crucial entender que **Redux no es exclusivo de React**. Es una librería independiente de JavaScript que se puede usar con Angular, Vue, o incluso sin ningún framework.

Se basa en tres principios fundamentales:

  1. Única Fuente de Verdad: Todo el estado de tu aplicación reside en un único objeto (el **Store**).
  2. El Estado es de Solo Lectura: La única forma de cambiar el estado es emitiendo una **Acción** (un objeto que describe qué pasó).
  3. Los Cambios se Hacen con Funciones Puras: Para especificar cómo cambia el estado en respuesta a una acción, escribes funciones puras llamadas **Reducers**.

Conceptos Clave de Redux

  • Store: El contenedor central que guarda todo el estado (state).
  • State: Un objeto JavaScript simple que representa los datos de tu aplicación en un momento dado.
  • Action: Un objeto simple que describe un evento que ocurrió. Obligatoriamente tiene una propiedad type (un string) y opcionalmente puede llevar datos (payload). Ej: { type: 'INCREMENTAR_CONTADOR', payload: 1 }.
  • Reducer: Una función pura que toma el estado actual y una acción, y devuelve el **nuevo** estado. Nunca modifica el estado original. Firma: (currentState, action) => newState.
  • Dispatch: La función del store que usas para enviar (despachar) acciones al reducer.
  • Subscribe: La función del store que te permite registrar un "listener" que se ejecutará cada vez que el estado cambie.

Ejemplo Simple (Vanilla JavaScript)

Imaginemos un contador simple usando solo Redux.

Nota sobre el entorno: El siguiente ejemplo usa la variable global Redux (cargada desde el CDN). En un proyecto real con bundler, importarías con import { createStore } from 'redux'. Este script solo funciona en este HTML plano. 

// En un entorno real con bundler:
// import { createStore } from 'redux';

// 1. El Reducer: Decide cómo cambia el estado
function counterReducer(state = { value: 0 }, action) {
  switch (action.type) {
    case 'INCREMENT':
      // Devuelve un NUEVO objeto de estado
      return { value: state.value + 1 };
    case 'DECREMENT':
      return { value: state.value - 1 };
    default:
      // Si no reconoce la acción, devuelve el estado sin cambios
      return state;
  }
}

// 2. Crear el Store con el reducer
const store = Redux.createStore(counterReducer); // Usamos Redux global en este HTML

// 3. Subscribe: Función que se ejecuta al cambiar el estado
store.subscribe(() => {
  console.log('El estado cambió:', store.getState());
});

// 4. Dispatch: Enviar acciones para cambiar el estado
console.log('Estado inicial:', store.getState());

store.dispatch({ type: 'INCREMENT' }); // Output: El estado cambió: { value: 1 }
store.dispatch({ type: 'INCREMENT' }); // Output: El estado cambió: { value: 2 }
store.dispatch({ type: 'DECREMENT' }); // Output: El estado cambió: { value: 1 }

Parte 2: React Redux - Conectando Redux con React 🔗

Redux por sí solo no sabe nada de React. Necesitamos un "puente" para conectar nuestro store de Redux con nuestros componentes de React. Ese puente es la librería **react-redux**.

react-redux nos proporciona herramientas para:

  • Hacer que el store de Redux esté disponible para toda la aplicación React.
  • Permitir que los componentes "lean" datos del estado de Redux.
  • Permitir que los componentes "despachen" acciones para actualizar el estado.
  • Asegurar que los componentes se re-rendericen automáticamente cuando cambian los datos del store que les interesan.

Herramientas Clave de react-redux

  • <Provider store={store}>: Un componente que envuelve tu aplicación (usualmente en main.jsx o index.js). Hace que el store de Redux esté disponible para cualquier componente anidado que lo necesite.
  • useSelector(selectorFunction): Un hook que permite a un componente funcional **leer** datos del store. La selectorFunction recibe todo el state y devuelve la porción específica que el componente necesita. React Redux se encarga de volver a renderizar el componente si ese dato cambia.
  • useDispatch(): Un hook que devuelve la función dispatch del store. La usas para enviar acciones desde tus componentes.
Antes de los Hooks: Existía una función llamada connect que hacía un trabajo similar, pero era más compleja de usar. Con los hooks useSelector y useDispatch, la integración es mucho más sencilla e intuitiva.

Parte 3: Redux Toolkit (RTK) - La Forma Moderna y Simplificada ✨

Escribir Redux "a mano" (como en el ejemplo de Vanilla JS) puede ser verboso:

  • Crear constantes para los tipos de acción.
  • Escribir "action creators" (funciones que devuelven objetos de acción).
  • Configurar el store con middleware (como Thunk para acciones asíncronas) puede ser complicado.
  • Manejar la inmutabilidad (no modificar el estado directamente) requiere cuidado (ej. usar ...spread operator).

Redux Toolkit (RTK) es la forma **oficial y recomendada** de escribir lógica de Redux hoy en día. Fue creado por el equipo de Redux para simplificar todo esto.

Beneficios Clave de RTK

  • Menos Código (Boilerplate): Reduce drásticamente la cantidad de código repetitivo.
  • Configuración Simple: configureStore configura automáticamente herramientas útiles como Redux DevTools y Thunk.
  • Inmutabilidad Simplificada: Usa una librería llamada Immer "bajo el capó", que te permite escribir código que *parece* mutar el estado, pero Immer se encarga de producir el nuevo estado inmutable correctamente.
  • Buenas Prácticas Incluidas: Fomenta una estructura de código más organizada y mantenible.

Herramientas Clave de RTK

  • configureStore(): Reemplaza al createStore original. Simplifica la configuración del store, incluyendo reducers, middleware y DevTools.
  • createSlice(): ¡La joya de RTK! Permite definir un reducer, sus acciones y el estado inicial en un solo lugar.
    • Automáticamente genera los "action creators" y los "action types".
    • Permite escribir lógica de reducer "mutante" gracias a Immer.
  • createAsyncThunk(): Simplifica el manejo de acciones asíncronas (como llamadas a API).

Ejemplo del Contador con RTK y React

Veamos cómo se ve nuestro contador usando RTK y los hooks de react-redux.

Paso 1: Crear el "Slice" (features/counter/counterSlice.js)


import { createSlice } from '@reduxjs/toolkit';

// Estado inicial para este "slice" (pedazo) del estado global
const initialState = {
  value: 0,
};

// Creamos el slice
export const counterSlice = createSlice({
  name: 'counter', // Nombre del slice
  initialState,
  // Los "reducers" definen las acciones y cómo actualizan el estado
  reducers: {
    // Acción 'increment': El estado aquí SÍ se puede "mutar" gracias a Immer
    increment: (state) => {
      state.value += 1;
    },
    decrement: (state) => {
      state.value -= 1;
    },
    // Acción que recibe un payload (valor)
    incrementByAmount: (state, action) => {
      state.value += action.payload;
    },
    // Acción para resetear
    reset: (state) => {
      state.value = 0;
    },
  },
});

// Exportamos las acciones generadas automáticamente por createSlice
export const { increment, decrement, incrementByAmount, reset } = counterSlice.actions;

// Exportamos el reducer generado para usarlo en el store
export default counterSlice.reducer;

Paso 2: Configurar el Store (app/store.js)


import { configureStore } from '@reduxjs/toolkit';
// Importamos el reducer que creamos
import counterReducer from '../features/counter/counterSlice';

// configureStore combina reducers y configura middleware útil
export const store = configureStore({
  reducer: {
    // Aquí definimos la estructura de nuestro estado global
    // 'counter' será la clave para acceder al estado del counterSlice
    counter: counterReducer,
    // Podríamos añadir más reducers aquí (ej. user: userReducer)
  },
});

Paso 3: Proveer el Store (main.jsx o index.js)


import React from 'react';
import ReactDOM from 'react-dom/client';
import { Provider } from 'react-redux'; // Importar Provider de react-redux
import { store } from './app/store'; // Importar nuestro store configurado
import App from './App';
import 'bootstrap/dist/css/bootstrap.min.css';

const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(
  <React.StrictMode>
    {/* Envolvemos la App con el Provider y le pasamos el store */}
    <Provider store={store}>
      <App />
    </Provider>
  </React.StrictMode>
);

Paso 4: Usar el Estado y las Acciones en un Componente (features/counter/Counter.js)


import React from 'react';
import { useSelector, useDispatch } from 'react-redux';
// Importamos las acciones que exportamos desde el slice
import { increment, decrement, incrementByAmount, reset } from './counterSlice';

export function Counter() {
  // 1. Leer datos del store con useSelector
  //    El 'state.counter' coincide con la clave que definimos en configureStore
  const count = useSelector((state) => state.counter.value);
  
  // 2. Obtener la función dispatch para enviar acciones
  const dispatch = useDispatch();

  return (
    <div className="card shadow-sm">
      <div className="card-body text-center">
        <h2 className="card-title">Contador Redux</h2>
        <p className="display-4">{count}</p>
        <div className="btn-group mb-3">
          <button 
            className="btn btn-primary" 
            onClick={() => dispatch(increment())} // Despachamos la acción importada
          >
            +1 (Incrementar)
          </button>
          <button 
            className="btn btn-secondary" 
            onClick={() => dispatch(decrement())}
          >
            -1 (Decrementar)
          </button>
          <button 
            className="btn btn-success" 
            onClick={() => dispatch(incrementByAmount(5))} // Acción con payload
          >
            +5
          </button>
          <button 
            className="btn btn-warning" 
            onClick={() => dispatch(reset())} // Acción sin payload
          >
            Reset
          </button>
        </div>
      </div>
    </div>
  );
}

Bonus: Acciones Asíncronas con createAsyncThunk 🌐

Cuando necesitamos hacer llamadas a una API dentro de Redux, createAsyncThunk simplifica el manejo de los tres estados: pending, fulfilled y rejected.

Ejemplo: Obtener usuarios


import { createSlice, createAsyncThunk } from '@reduxjs/toolkit';

// 1. Crear el thunk asíncrono
export const fetchUsers = createAsyncThunk(
  'users/fetchUsers',
  async () => {
    const response = await fetch('https://jsonplaceholder.typicode.com/users');
    return response.json();
  }
);

const usersSlice = createSlice({
  name: 'users',
  initialState: {
    items: [],
    status: 'idle', // 'idle' | 'loading' | 'succeeded' | 'failed'
    error: null,
  },
  reducers: {},
  // 2. Manejar los estados del thunk con extraReducers
  extraReducers: (builder) => {
    builder
      .addCase(fetchUsers.pending, (state) => {
        state.status = 'loading';
      })
      .addCase(fetchUsers.fulfilled, (state, action) => {
        state.status = 'succeeded';
        state.items = action.payload;
      })
      .addCase(fetchUsers.rejected, (state, action) => {
        state.status = 'failed';
        state.error = action.error.message;
      });
  },
});

export default usersSlice.reducer;

En el componente, se despacha el thunk y se usa el estado status para mostrar un spinner o los datos.
